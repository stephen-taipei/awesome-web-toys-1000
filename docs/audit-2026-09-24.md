## Scope and boundaries

The inventory covers all 1,005 toy directories, 1,005 JavaScript files, local HTML asset/link targets, and both XML sitemaps. There are 1,000 numeric IDs with five additional alternate topics at IDs 996-1000. Existing slugs are retained. No toy was deleted or renumbered.

The root landing page's body and inline CSS remain byte-identical to the baseline. No CSS file changes are included. The only root HTML change corrects `/llms.txt` to `llms.txt` so the metadata URL works under the GitHub Pages project prefix. The source test protects the approved body and style hashes.

This audit combines full inventory, static checks, automated startup coverage, and targeted source review with interaction/resource-lifecycle regressions. It does not claim manual line-by-line review of every toy or complete behavioral acceptance of every simulation.

## Reproducible verification

```sh
python3 scripts/audit.py
python3 -m unittest discover -s tests -p 'test_*.py'
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements.txt
python -m playwright install chromium
python tests/browser.py --suite all
```

The Python browser test dependency is pinned in `tests/requirements.txt`. No runtime dependency or bundler was added to any toy. CI uses read-only repository permissions, full upstream-verified action commit SHAs, no persisted checkout credentials, finite timeouts, and failure evidence artifacts.

The browser gate defaults to a real HTTP server at a repository subpath. `--inline` is an explicitly reported alternative for restricted environments. It injects the same local CSS/JavaScript into the HTML and **does not test HTTP routing, origin security or deployment headers**.

## Remaining work and acceptance limits

1. **Accessibility:** 164 form controls still need contextual naming review. Canvas alternatives, full keyboard access, reduced-motion behavior, contrast, touch gestures and screen-reader flows require a separate acceptance pass. The 473 label associations alone do not establish compliance.
2. **Device coverage:** Validate supported microphone flows, WebGL/WebGPU, device sensors, Local Font Access, Window Management, Ink and WebCodecs on actual target browsers/devices. Firefox, Safari/iOS and Android hardware were not exercised here. Five targeted toys have mobile viewport startup coverage, not the whole collection.
3. **Performance and behavior:** Add longer interaction/soak tests, deterministic simulation invariants and per-toy performance budgets. The current all-page sweep does not verify every button, export format, mathematical result or sustained animation workload.
4. **Discovery/deployment:** Existing sitemap URLs resolve to source pages. Remote production responses, response headers and site-root robots configuration were not audited. A project-subpath `robots.txt` cannot substitute for deployment-level configuration at the origin root.
5. **Licensing:** The existing README declares MIT but the repository has no standalone `LICENSE` file. The maintainer should confirm ownership and the intended complete grant before adding it. This repair does not relicense code or assert rights to third-party content.
6. **Maintenance architecture:** Preserve standalone toy packaging for now. Repeated lifecycle code is covered by one shared test matrix. A future shared module should be adopted only with an explicit decision about standalone copy/paste use and equivalent per-toy regression coverage.

No device data, user files, production secrets, external analytics or runtime network dependencies were added. Permission denial remains a supported user choice.
